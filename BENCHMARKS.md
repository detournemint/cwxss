# Benchmarks

Recorded so that a change can be judged rather than asserted. Every figure is
character accuracy by edit distance against known text.

Reproduce with:

    python3 cwxss/eval.py --model models/cw.pt --trials 8      # synthetic
    python3 cwxss/eval_real.py --model models/cw.onnx          # real recordings

## Synthetic

Generated by `synth.py`, so the conditions are named and fixed and the labels
are exact. Eight clips per condition.

| condition | classic | neural |
|---|---|---|
| clean keyer 20 wpm | 100.0% | 100.0% |
| clean keyer 30 wpm | 100.0% | 100.0% |
| good operator 18 wpm | 100.0% | 100.0% |
| rough fist 18 wpm | 68.4% | **88.9%** |
| bug key 20 wpm | 66.5% | **95.7%** |
| Farnsworth 20/12 | 63.7% | **100.0%** |
| weak 6 dB | 100.0% | 100.0% |
| weak 3 dB | 89.5% | **100.0%** |
| QSB deep fade | 65.4% | **98.8%** |
| static crashes | 98.6% | 100.0% |
| QRM 150 Hz away | 100.0% | 100.0% |
| rough + weak + QRN | 60.1% | **89.0%** |
| **mean** | **84.4%** | **97.7%** |

The model wins everything the classic decoder fails and gives up nothing where
it does not. The two things that make real CW hard -- a human fist and
Farnsworth spacing -- are the two it improves most.

## Real recordings

ARRL W1AW code practice files, which come with exact transcripts. Machine-sent
and studio-clean, so they are a test of reading text we did not write at speeds
we did not choose, not a test of weak-signal work.

Nine files, 5 to 40 wpm. ARRL publishes no archive for 25 or 35 wpm.

| file | classic | neural |
|---|---|---|
| **5 wpm** (15 wpm chars, 3:1 Farnsworth) | 35.2% | **53.3%** |
| **10 wpm** | 29.9% | **62.7%** |
| 13 wpm | 71.1% | 68.4% |
| 13 wpm (second) | 72.4% | 68.6% |
| 15 wpm | 79.1% | 79.5% |
| 18 wpm | 78.2% | 72.5% |
| 20 wpm | **78.9%** | 77.1% |
| 30 wpm | **85.0%** | 75.5% |
| 40 wpm | **87.7%** | 80.4% |
| **mean** | **68.6%** | **70.9%** |

The split is clean and it is the useful result: **the model wins where the
timing is irregular and the classic decoder wins where it is exact.** Below
13 wpm ARRL sends heavy Farnsworth and the classic decoder puts a word break
between every letter, scoring 30-35% with every letter correct. Above 20 wpm the
timing is machine-exact, there is nothing for a model to add, and the classic
decoder is ahead by 2 to 9 points.

That argues for running both and choosing by measured regularity, rather than
replacing one with the other.

### The benchmark had a bug worth recording

The first run of this expanded set scored the model at 8.7% on the 7.5 wpm file
and put it behind the classic decoder overall. The decode was
`PL259 FORMAT CONNECTOR` -- perfectly good copy. The transcript had downloaded
as binary, and the model was being scored against nonsense.

`eval_real.py` now checks that a reference is readable text before scoring
against it. A benchmark that silently accepts a corrupt reference is worse than
no benchmark: it produces confident numbers that are wrong, and it nearly caused
a good model to be judged a regression.

## History

| date | change | synthetic | real |
|---|---|---|---|
| initial | classic decoder only | 84.4% | 68.5% |
| 4000 steps | first trained model | 96.1% | 66.1% |
| 9000 steps | Farnsworth to 3.2:1, speeds from 8 wpm | **97.7%** | 68.6% |
| benchmark | expanded 5 real files to 9, fixed a corrupt reference | 97.7% | **70.9%** |

The 4000-step model beat the classic decoder comfortably on synthetic while
losing to it on real recordings -- a reminder that a model can win on its own
test set. Widening the training distribution after measuring against the real
files closed that gap: the 5 wpm file went from 43.5% to 53.3% and the real mean
from 66.1% to 68.6%.

## Compared with other decoders

Run head to head on identical clips against [DeepCW](https://github.com/e04/deepcw-engine)
(15 MB model, spectrogram input) versus ours (710 KB, envelope input):

| clip | DeepCW | ours |
|---|---|---|
| clean 20 wpm | exact | exact |
| weak 3 dB | exact | exact |
| rough fist | 1 error | 2 errors |
| bug key | 1 error | **exact** |
| Farnsworth | exact | exact |
| QSB | exact | 1 error |
| static crashes | exact | exact |

Below about -6 dB neither decodes, but DeepCW falls silent while ours produced
confident nonsense -- which is what led to the confidence gating described in
the README.

SNR figures are not comparable between projects without a stated reference
bandwidth. Ours is 500 Hz.
